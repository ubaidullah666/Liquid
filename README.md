# Liquid Glass

A Windows desktop application with a Blender glass orb, Ollama chat with persistent memory and selectable local or cloud models, and an animated transformation into an embedded Chromium web browser.

**New chat** starts an empty conversation. Each time you close and reopen the app, it also starts a fresh chat. Previous conversations stay saved: click **History**, then choose a conversation to view and continue it, or search all saved messages. Starting a new chat does not erase your saved memory. Stop an active reply before changing chats.

Double-click **Launch Liquid Glass.cmd** to open. Choose a model below the message field; the default is **qwen2.5:3b**. The selected model answers through your local Ollama service at `http://127.0.0.1:11434`. Replies stream into the conversation; the square Stop button cancels generation. Keep Ollama running. If necessary, install the model with `ollama pull qwen2.5:3b`.

Browser mode opens only on an explicit command such as **open browser**, **search cats on browser**, or **open wikipedia.org in browser**. A plain question, a pasted URL, or “search for an explanation” remains a local chat message. The orb stretches into the browsing surface and the same glass field moves to the address-bar position. **Search that on browser** searches the last normal message. Click **LIQUID** in the upper left to return to chat; open tabs stay available when you return to browsing.

All user messages, assistant replies, typed browser requests and calendar changes are saved automatically in `profiles/<profile-id>/conversation-history.jsonl` under the app's Windows user-data directory (normally `%APPDATA%/liquid-glass`). History survives closing and reopening the app. Click **History** to search saved messages; **Load earlier messages** retrieves older entries. No history is discarded to make room for a model request: the model receives a bounded recent conversation plus relevant older records and remembered personal facts. A finite context window and model limitations mean recall is not infallible. Interrupted answers are checkpointed during streaming and marked if stopped or failed. The local file is plain text, so keep it private if your conversations are sensitive. Existing history is copied into the first Personal profile without removing the original.

**Calendar** opens your local agenda. Add events with start/end times, edit them or delete them. Events persist separately in each profile. Chat receives a bounded calendar snapshot and can answer schedule questions; event changes use the Calendar form. No Google account, OAuth, cloud calendar, background reminders or external calendar synchronization is used.

Click your profile name to create or switch profiles. Profiles keep separate history, calendar data, and browser sessions. Windows Hello locking has been removed, including from previously protected profiles.

Web pages run inside this application's window using Electron 44 / Chromium. The browser supports multiple tabs, back and forward navigation, reload and stop, web searches, website forms, links that open new tabs, persistent cookies and site storage, downloads with a save dialog, find on page, zoom, printing, and fullscreen. Downloads are reported in the bottom status bar. The three-dot menu contains additional controls. The page itself supports normal scrolling, text entry, file-upload dialogs, and a right-click menu.

Shortcuts: **Ctrl+L** address bar; **Ctrl+T** new tab; **Ctrl+W** close tab; **Ctrl+Tab** next tab; **Ctrl+Shift+Tab** previous tab; **Alt+Left/Right** back/forward; **Ctrl+R** or **F5** reload; **Ctrl+F** find; **Ctrl +/-/0** zoom; **F11** fullscreen.

Local inference runs on this computer. Web search sends queries to Ollama search when enabled. Cloud selections send the message, relevant saved history, and calendar context through local Ollama to Ollama Cloud. The picker labels cloud models before use. Explicit browser searches are sent to Google; visited websites receive normal browser requests and can store cookies in the app's separate persistent profile. Website code has no access to the chat/history bridge, desktop-control bridge, or Node.js. Camera, microphone, location, notifications, clipboard reading, and other supported permissions require a native prompt. Unsupported external-app links stay blocked within the app, and certificate errors are not bypassed. Codex can create project files and run terminal commands when model terminal access is enabled.

This is a custom Chromium browser, not a full Chrome distribution. Chrome extensions, account sync, a built-in password manager, and DRM streaming integrations are not included. Some services restrict embedded browsers or require additional integrations. It has no automatic runtime updater; update Electron and rebuild to take future Chromium security updates.

The editable Blender source is `blender/liquid-orb.blend`. `blender/create_orb.py` builds the mesh, glass material, and looping shape-key animation. The application loads its exported `assets/liquid-orb.glb`, using a real-time studio reflection environment and glass material for interactive rendering.

Development: `npm install`, then `npm start`. Build a portable Windows app with `npm run package`. Regenerate the Blender asset with `blender --background --python blender/create_orb.py`. Run `npm run check` for syntax and command-parsing tests. Run `node_modules/electron/dist/electron.exe . --browser-test` for the real-window integration checks (including a local test server and external HTTPS check). Test browsing uses a separate temporary browser partition and profile directory, and does not use your browsing session.

Chat integration checks: run `node_modules/electron/dist/electron.exe . --chat-test`, then rerun with `--chat-test --recall`. These use actual local Qwen generation and a separate `.chat-test-profile` to verify memory across process restarts without adding test messages to your real history.

Reduced-motion system preferences are respected. A graphics driver with WebGL 2 support is required.

**Attachments:** Use **Add files** to attach up to five files, 8 MB each. Text/source files, DOCX, text-based PDFs and images are supported. Images require a vision model; scanned PDFs require external OCR. Extracted text is bounded, saved with history and sent to the selected model, including cloud models when selected.

**Downloads and preview:** Codex code blocks now offer **Download**, opening a save dialog in Downloads. HTML, CSS and JavaScript Preview opens in the built-in Liquid browser with generated assets. Preview project serves an HTML entry from the selected folder, preferring dist or build output. Framework projects requiring compilation must be built or started in Terminal first.

**Web search and Deep thinking:** Web search sends queries through your signed-in Ollama service, including when using local models. Retrieved source links appear in chat. Tool-capable models can request additional searches. Deep thinking uses native model support and is available only on compatible models. The app shows thinking progress without displaying private reasoning. Options are separate for each conversation.

Local web answers use compact search excerpts directly; cloud models with tool support may perform follow-up searches. Token-limited answers automatically continue up to three times. Thinking-only responses retry once with thinking disabled or reduced where supported, then show an explicit error if no answer is returned. Coding and Deep thinking requests allow up to 20 minutes; Stop remains available throughout.

**Codex terminal:** Open **Terminal**, choose a project folder and enter PowerShell commands to see live output. Stop cancels a command. Enable **Allow model terminal** to let a tool-capable model run commands while answering. Commands run under your Windows account with a 60-second limit, bounded output and no interactive input. Model terminal access starts disabled. Codex models with tool support can also create new project files; the file-creation tool preserves existing files.

Feature integration check: `node_modules/electron/dist/electron.exe . --features-test` verifies the controls and actual HTML preview with linked CSS/JavaScript in a separate test profile. Results are saved to `features-test-result.json`.

**Code in chat:** Ask the selected model to write code using the normal message field. Code appears in editable blocks with Copy and Save controls. Click Run for JavaScript or Python to see output, errors, and exit status directly in chat; Stop cancels execution. HTML blocks offer Preview in the built-in Liquid browser. JavaScript uses the bundled runtime; Python needs a local Python 3 installation with the Windows py launcher. Programs run under your Windows account in a temporary working folder, with no interactive input, a 15-second limit, and a 64 KB output limit. Run only code you trust: local script execution is not a security sandbox. Run results and the executed source are saved with the conversation. Edited drafts should be copied or saved before reopening the app. Other languages can be edited and saved.


**Models:** The model picker lists downloaded local models and configured Ollama cloud models, grouped by location. Refresh updates the list after changes in Ollama. The choice is saved separately for each profile and applies to both chat and code generation; old replies retain the model that produced them. Stop the current answer or program before changing models. To use another cloud model, expand Cloud model and enter its exact Ollama cloud tag (ending in :cloud or -cloud). Sign in with `ollama signin` first; no API key is stored in this app. Cloud inference needs internet access and an eligible Ollama account. See https://docs.ollama.com/api/authentication for sign-in and https://docs.ollama.com/cloud for model discovery.

**Chat / Codex:** Use the two mode buttons in the header. Chat handles questions, information, and conversation; its instructions route implementation requests to Codex, and file creation, saving source files, and program execution are blocked in Chat. Codex handles coding and text/source file creation using your selected Ollama model. Each mode has separate current conversations, saved-history lists, and model context. Switching returns to the current conversation for that mode; New chat starts another conversation in the selected mode. The app starts in Chat.

In Codex, choose **Project folder…**. Ask for a file or a project; generated blocks include relative filenames. Review or edit the filename and content, then click **Create file** to create it inside your project folder (including subfolders). Existing files are preserved; use **Save…** to select a different path or explicitly replace a file through the save dialog. Python/JavaScript support Run; HTML supports Preview. Created-file activities and execution results are recorded in Codex history. Project-folder selection lasts for the running app session and is separate for each profile.


The composer supports multiple lines: Enter sends, Shift+Enter inserts a line break. Clear chat deletes the current conversation. History contains Delete conversation and Delete all history controls; deletion permanently removes saved records from the active profile, including older revisions. Delete all history covers both Chat and Codex. Each deletion asks for confirmation.
